# roi-site · One-shot v3 (удобная настройка ESP32)

Это обновление для существующего проекта `Tfhguk/roi-site`. Сайт остается статическим на GitHub Pages, локальный компьютер обеспечивает сервер, ArUco и управление двигателями.

## Сначала установка

Распаковать ZIP патча, затем из терминала:

```bat
py -3 apply.py "C:\path\to\roi-site" --check
py -3 apply.py "C:\path\to\roi-site"
cd /d "C:\path\to\roi-site"
npm install
npm run test:oneshot
npm run build
```

Если v2 уже установлен, v3 обновит его безопасно, не теряя токены и резервные копии. Никогда не накладывай патч на папку скачанного патча: указывай именно корень репозитория `roi-site`.

## Потом настройка, без ручного получения токенов

1. Открыть `SUPABASE_SETUP_RU.md`.
2. В существующем Supabase выполнить `supabase/robot-cloud-migration.sql` (один раз).
3. Запустить **SETUP-ROBOTS-WINDOWS.cmd** (из корня `roi-site`).
4. Мастер попытается самостоятельно заполнить Project URL и publishable key. Если не найдет, взять публичные значения из Dashboard → Connect.
5. Войти в аккаунт «Гаража» и загрузить список техники. Выбрать роботов и нажать кнопку создания конфигурации.
6. У каждого робота появятся действия «Показать токен», «Копировать» и «Скачать прошивку». Последняя берет токен непосредственно из локальной конфигурации; совпадение гарантировано.
7. Указать Wi-Fi SSID/пароль и IP компьютера. Скачать персональный ZIP и прошить через Arduino IDE.
8. Остановить мастер (Ctrl+C). Запустить **START-ROBOTS-WINDOWS.cmd**.
9. Измерить полигон, заполнить `arena.polygon` и четыре опорных ArUco в `tracker-private.json`, откалибровать моторы/датчик АКБ. Проверить аварийные остановки на отключенных и приподнятых колесах.
10. После калибровки задать корректные параметры модели и только тогда снимать программную блокировку движения.

## Изменено по сравнению с v2

- Кнопка прошивки в карточке теперь открывает понятный мастер, а не предлагает пользователю вручную вводить токены.
- Создан локальный пошаговый мастер с входом в Supabase (пароль или email OTP), выбором техники из БД и генерацией всех локальных секретов.
- `cloud.refreshToken` получается при входе, не нужно копировать его из браузера; мастер сохраняет токен на локальном ПК.
- Персональный `config.h` добавляется в ZIP автоматически. Кнопки «Показать токен» и «Копировать» действуют в локальном мастере.
- Ни один токен робота, оператора, трекера и Supabase RefreshToken не должен попадать в публичный репозиторий.
- Умышленно не создается выдуманный полигон 3×3 м, режим движения заблокирован до калибровки.

## Безопасность и ограничения

Тестирование исходного кода не равнозначно тестированию на железе. Web Serial не используется: прошивка скачивается в ZIP, загрузка через Arduino IDE. Для камеры потребуются Python, OpenCV-contrib и numpy. Токены не выводятся в консоль или общедоступные JS файлы. Приватные файлы перечислены в `.gitignore`.

Если автоматическое определение URL/key не удалось, они вводятся один раз вручную. Вход через Supabase Auth требует совпадения с методом входа, используемым на сайте. Для OTP по коду может потребоваться изменение шаблона email в Supabase.
