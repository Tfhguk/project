# Куборги / настройка Supabase и реальных роботов

## Что нужно приготовить

- Компьютер Windows с установленным **Node.js 20+**, камерой и доступом в интернет.
- Исходники **roi-site** с примененным патчем v3.
- Свой аккаунт в **существующем** проекте Supabase, где уже работает «Гараж».
- Технику с привязанным ArUco ID. Каждый робот имеет свой UUID, не путать с номером ArUco.

## Быстрый путь, без ручных токенов

1. Дважды нажми **SETUP-ROBOTS-WINDOWS.cmd** в корне каталога `roi-site`.
2. Мастер откроется в браузере на `http://127.0.0.1:8767`. Если не открылся, перейди по локальной ссылке в окне Node.js. Не публикуй эту ссылку.
3. Если адрес и ключ Supabase нашлись в исходниках, они уже будут введены. В противном случае см. ниже пункт «Публичные параметры».
4. Войди **под своей почтой и паролем Supabase Auth, тем же аккаунтом, которым пользуешься в «Гараже»**. Пароль не сохраняется. Если система использует код из письма, можно попробовать email OTP (см. примечание ниже).
5. Нажми **«Загрузить технику из Гаража»**. Выбери роботов, проверь номер ArUco и UUID полигона, нажми **«Создать конфигурацию и все токены»**.
6. На экране появятся роботы. У каждого: **«Показать токен»**, **«Копировать»**, **«Скачать прошивку»**. Поля Wi-Fi нужны только для персонального ZIP прошивки и не попадают в `robot-private.json`.
7. Закрой мастер (Ctrl+C в его консоли). Запусти **START-ROBOTS-WINDOWS.cmd**. На первом запуске движение запрещено до измерения геометрии полигона и калибровки модели.

> Из терминов нужны только **«аккаунт»**, **«номер ArUco»**, **«проект Supabase»** и **«адрес компьютера в сети»**. Пользователю не нужно вручную искать RefreshToken, TrackerToken, операторский токен или UUID из базы.

## Публичные параметры Supabase: где брать

1. Открой [https://supabase.com/dashboard/projects](https://supabase.com/dashboard/projects).
2. Выбери **тот же проект, который уже использует сайт**.
3. Нажми **Connect** и найди Project URL `https://xxxxx.supabase.co`, а также **Publishable key** вида `sb_publishable_...`.
4. Альтернативно открой **Project Settings → API Keys**. Если проект старый и publishable key отсутствует, создай его; legacy `anon` JWT пока поддерживается, если действительно имеет роль `anon`.
5. Вставь **только эти два публичных значения** в мастер. Административные ключи `sb_secret_...` и `service_role` вообще не нужны.

Справка Supabase: https://supabase.com/docs/guides/getting-started/api-keys

## Подготовка базы данных (администратор проекта, один раз)

1. В Dashboard проекта выбери **SQL Editor → New query**.
2. Открой в репозитории `supabase/robot-cloud-migration.sql`, скопируй содержимое целиком, вставь в SQL Editor.
3. Убедись, что в этом проекте уже есть таблица `public.equipment`, созданная «Гаражом» (и связанная с `auth.users`).
4. Выполни SQL. Он добавит очереди `robot_jobs` и состояния `robot_states` с RLS. Без этой операции кнопка управления будет получать ошибку PostgREST о несуществующей таблице.
5. Не запускай миграцию в другом проекте и не отключай RLS ради отладки.

### А что такое RefreshToken?

Это служебный ключ для автоматического обновления авторизации. Мастер получает его в момент входа и записывает в **приватный файл** `local/robot-private.json`. После этого локальный сервер автоматически обновляет его по HTTPS. Вручную его искать, копировать и передавать в чат не нужно. Не загружай `robot-private.json` в GitHub.

Если для аккаунта разрешен только вход по ссылке из почты, а пароля нет, в мастере есть режим **OTP**. Для **числового кода** почтовый шаблон Supabase должен включать `{{ .Token }}`. Без соответствующей настройки придет magic link вместо числового кода. Либо используй отдельного пользователя-оператора с паролем и доступом к своей технике.

## Что с остальными токенами

| Что спрашивал старый патч | Откуда теперь берется |
|---|---|
| Токен пользователя | Не нужен как отдельное поле. Supabase определяет пользователя по сессии. |
| Токен полигона | Не нужен. UUID полигона забирается из привязки техники, если поле есть в базе. |
| `operatorToken` | 32 случайных байта, мастер создает автоматически на локальном ПК. |
| `trackerToken` | Генерируется локально и автоматически дублируется в `local/tracker-private.json`. |
| `device.token` | Генерируется персонально и вставляется в `firmware/config.h` при скачивании ZIP. |
| `cloud.refreshToken` | Получается автоматически при входе, в интерфейсе не показывается. |
| `cloud.publishableKey` | Из исходников сайта, если найден; иначе из Dashboard → Connect. |

Если меняешь пароль пользователя или отзываешь его сессию, подключение к Supabase может потребовать нового входа через мастер.

## Файлы и риски

`local/robot-private.json` хранит секреты и список роботов. `local/tracker-private.json` хранит ключ трекера и координаты четырех фиксированных маркеров для камеры. Эти файлы игнорируются Git. Ни один ключ не публикуется на GitHub Pages.

**Нельзя** включать автоматическое движение, пока в конфигурации не заданы измеренные границы `arena.polygon` в метрах, не откалибрована матмодель и не проверены датчики безопасности. Мастер не устанавливает ложный полигон 3×3 м и оставляет `model.calibrated=false`.

Установка Python-библиотек для трекера: `pip install opencv-contrib-python numpy`. Настройка якорных ArUco-маркеров и ориентации на физическом полигоне обязательна.

### Если не получается

- **Неверный URL/ключ**: проверь, что они от одного проекта; секретный ключ не используется.
- **Логин не работает**: это пароль учетной записи **Supabase Auth**, не пароль Dashboard администратора. Проверь способ входа на сайте «Гаража».
- **Нет роботов**: аккаунт не владелец записей `public.equipment` либо таблица имеет другую структуру.
- **Скачивание ZIP не работает**: проверь наличие `firmware/hardware.h` и `firmware/hardware-config.h` в установленном `roi-site`.
- **IP сервера**: выбери IPv4 того интерфейса, который доступен ESP32; `127.0.0.1` использовать нельзя.
- **STOP и ошибки**: при потере связи, низком напряжении и выходе за полигон остановка должна происходить на ESP32 и сервере. Физическую систему испытать отдельно.

## Если хочешь помочь с настройкой, а не передавать секреты

Можно прислать **URL проекта** `https://xxxxx.supabase.co`, **названия колонок** таблицы `equipment`, скриншот `Project Settings → API Keys` с замазанными значениями ключей, а также текст ошибки. Этого достаточно для проверки схемы интеграции. Пароль, refresh token, токены роботов, `service_role` и `sb_secret_...` в чат не присылай.
